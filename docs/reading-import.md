# 书架：分类、导入批次与回收站

## 页面组织

书架把主要操作分开：顶层「未完成」「已完成」决定正在处理还是回看资料；紧凑类型入口决定看书籍、视频、课程教程、GitHub、文章还是两种日报。主题分类另列为筛选，避免把媒介类型、主题和完成状态混成同一组。

标记完成后保留打勾与淡出，记录完成时间；内容仍保存在同一条记录中，可以重新开始、编辑和移除。封面和笔记保留，页面刷新不重置状态。旧记录若没有可靠的完成时间，不推算历史日期。

## 视频候选规则

- 最近 7 × 24 小时的观看记录；时间必须有明确时区。窗口在提交时重新核验。
- 已知播放位置严格低于 25%；未知不能当成 0，多 P 当前分集位置不等于整门课程进度。
- 教育和实用内容分为十类：编程 / AI、科技、设计、自然科学、人文社科、语言、商业 / 经济、效率 / 职业、生活技能、其他 / 待分类。
- 编程课程、AI 开发与技术实践归「编程 / AI」；科技资讯、产品技术与新功能归「科技」，不因为属于新闻就一律留待确认。推广、夸张宣传或价值不明确的标题仍需审阅。
- 明显的纯娱乐内容排除；主题不明确的条目留在预览待确认。用户可主动接收待确认项、取消本次候选，导入后仍可修改分类。
- 预览阶段用本地标题规则筛选候选，入架后交给本机 Qwen 整理主题。模型只读取元信息，不表示已观看视频或读完字幕。手动改过的分类不会被再次导入覆盖。

B站采集来自已授权的登录浏览器页面。Codex 当前任务的「每日小院采集」已启用，每天纽约时间 **09:45** 运行；电脑须开机、Codex 须运行，B站须保持登录。网页单独打开不等于调度器在运行，启用也不等于未来的定时运行已执行成功。完整步骤和失败处理见 [每日采集说明](daily-collection.md)。

本网站和下面的 CLI 负责接收、校验、分类、去重和保存，不读取浏览器 cookie，也不声称拥有可靠的官方历史接口。登录失效或页面没读完整时记录实际覆盖；下一次仍重读最近一周并按来源去重，不能报告整个星期已经同步成功。模糊候选留在批次待确认，自动任务不替用户确认。

旧的 `programming` 与 `ai` 分类兼容显示为 `programming_ai`；「科技」与「商业 / 经济」的分类 ID 分别为 `technology`、`business`。读取旧记录不改写笔记、阅读状态、更新时间或导入撤销指纹；已明确设置的其他分类不重新推断，用户可自行调整。

## 输入与命令

### 网页快捷导入

书架右上角的「快捷导入」提供三种方式，均先预览再确认：

- **粘贴链接**：每行一个，支持 B站、文章、GitHub、网课、教程与有链接的书籍。可在预览中修正标题、类型、分类和随手记。
- **选择本机文件**：系统文件窗口可多选。PDF / EPUB 每份最多 50 MiB，UTF-8 Markdown / TXT 每份最多 2 MiB。工作台保存副本，入架后可打开或下载，原文件不动。Markdown / TXT 在卡片中展开纯文本预览；EPUB 下载后使用本机阅读器。
- **记一本书**：没有链接或电子文件也可记下书名和说明。

每批最多 30 项。文件窗口还支持 `.url`、XML `.webloc` 快捷方式以及 JSON / CSV 链接清单（每份最多 2 MiB）。JSON 为数组或带 `items` 的对象，每项必填 `url`，可选 `title`、`type`、`notes`、`category`；CSV 使用同名列，支持引号、逗号及换行。清单用于整理主动收藏的网页，不会按浏览历史的时间与播放比例筛掉内容。

```json
{"items":[{"url":"https://github.com/example/project","title":"想研究的项目","type":"github","notes":"了解它的数据可视化方式"}]}
```

类型 ID 为 `book`、`video`、`course`、`tutorial`、`github`、`article`。省略 `category` 即交给 Qwen；填写分类视为你的明确选择，模型不会覆盖。直接粘贴链接只提供域名、路径推断，暂不抓取文章正文或视频字幕；只有 BV 编号的标题建议在预览中补全，信息不足会进入待确认。

手动收藏不受「近一周、低于 25%」限制。重复和曾移除的来源仍会跳过，曾移除的内容可从回收站恢复。导入管理内的「历史记录 JSON」保留原来的历史候选规则。

### 分类与文件生命周期

确认后先保存条目，再异步排队分类。每次最多 8 条，只请求已有本机 Ollama 中的 Qwen；失败、超时或输出无效会保留内容并提供重试。高置信结果直接应用；其他结果提示确认建议，也可进入编辑手动选择。分类进行中若修改内容，旧结果失效；需要时重新分类。未结束的队列在工作台重启后继续，失败项不无限自动重试。既有日报按已知的科技 / 审美来源分类，不每天重复推理。

模型使用有长度限制的标题、网址、随手记与 Markdown / TXT 开头摘录。PDF / EPUB 当前仅用文件名、标题和随手记，不提取完整正文；资料仅在本机推理，不上传托管 API。模型的判断是建议，并不是对内容质量或准确性的认证。

上传只生成临时副本，取消预览即丢弃；意外中断留下的临时文件在 24 小时后、后续清理时移除。正式副本按内容哈希去重，存于个人数据旁的 `reading-attachments`，备份应与个人 JSON 一起复制。移除或撤销后仍可在 30 天回收站中恢复文件入口；恢复期结束后仅清理无人引用的工作台副本，原文件始终保留。

### 浏览历史 CLI

已实现命令使用 Node.js，运行时本机工作台须已启动。默认端口 3456，`--port` 仅可更改本机端口；不能指定外部服务器。

```powershell
node scripts/reading-import.mjs preview .runtime/history.local.json
node scripts/reading-import.mjs apply .runtime/history.local.json
node scripts/reading-import.mjs history
node scripts/reading-import.mjs undo <导入批次ID>
```

`preview` 不导入。`apply` 先请求预览校验，再提交相同输入，由服务端重新判断最新的重复、抑制和时间窗口；同时有人编辑或删除也不能被旧预览覆盖。所有写入经过 API，不直接改个人 JSON。输入文件、预览输出和浏览器记录放在被 Git 忽略的本机目录。

输入示意（链接和日期仅用于说明结构，使用时必须换成实际页面证据）：

```json
{
  "items": [
    {
      "title": "示例：摄影构图入门教程",
      "url": "https://www.bilibili.com/video/BV1234567890/",
      "viewedAt": "2026-09-27T09:00:00-04:00",
      "progress": 0.12,
      "notes": "来源页面显示 01:12 / 10:00；只代表这一分集的位置。"
    }
  ],
  "coverage": {
    "from": "2026-09-20T09:00:00-04:00",
    "to": "2026-09-27T09:00:00-04:00",
    "complete": true
  }
}
```

`progress` 是 0–1 的比例，不是 0–100 的百分数；`null` 表示未知。已有可见图片地址可通过 `coverUrl` 提供，仅接受受支持的 HTTPS B站图片来源。`acceptedUrls` 可显式接收主题待确认项，`excludedUrls` 可从本批排除条目；这些选择不能绕过时间、播放位置、明显娱乐、重复与删除抑制规则。

## 去重、移除与恢复

同一 B站 BV 视频只保留一份，分集信息作为观看证据保留；普通链接使用规范来源身份。导入先检查当前书架，再检查被移除来源，因此已完成内容不会被重新排入待读，删除的内容也不会在下一次导入中复活。

单项、多选和全部移除都进入书架回收站，保留原 ID、阅读状态、分类、笔记、封面和完成时间；回收站可单项或批量恢复，整批恢复原子完成。全部移除仍针对确认时列出的 ID 快照，不影响确认后才出现的新条目。移除日报只隐藏本地入口，不删除 PDF。

30 天内可恢复，也可以在回收站确认永久删除。永久删除会立即清除该条目的回收快照与无其他引用的托管附件副本；原文件、视频和日报 PDF 保留。来源抑制与导入决策审计仍保留，防止下次自动导入复活。到期后不可恢复完整快照，后续操作会清理过期正文。显式手动「收进书架」可以重新收藏一个旧来源并清除其抑制，但这是新记录；保留原 ID 和笔记应使用恢复。若同一来源已被重新手动收藏，恢复旧记录会提示冲突，避免重复或覆盖。

此前版本永久移除的内容没有回收站快照，不假装可以找回。已知的历史删除来源可登记为抑制记录；不会用旧备份还原整个数据库。书架移除不影响现有今日待办，也不删除原始视频或文件。

## 从书架加入待办

书籍、视频、课程、教程、GitHub 条目、文章、本机附件和正式日报都可以从条目上的「加入待办」创建任务。待办保留书架来源入口；从来源打开时会定位到对应条目，包括已经读完的内容。重复添加返回已有任务，任务完成后也不会重复创建。删除待办后，可以在书架上再次主动添加。

待办支持编辑标题与计划日期，也可以完成、重新打开或确认删除。待办完成表示这一次行动完成，书架的阅读状态仍由用户单独决定。例如「看第一讲」完成不意味着整个课程已读完。删除待办仅删除任务；移除书架内容仅影响书架，已有待办保留标题和来源快照，并提示来源不可用。恢复原书架条目会恢复关联；永久删除和附件清理不会因待办快照而被阻止。

接口：`POST /api/personal/reading/:id/todo`，JSON 为 `{}` 或可选的 `{ "title": "看第一讲", "dueDate": "2026-10-01" }`。首次返回 201 与 `{ todo, todoId, created: true }`，已有任务返回 200 与 `created: false`，不覆盖已有标题、日期和完成状态。默认标题取书架标题前 200 字，默认未设日期。不存在或已移除的条目返回 404。来源关联由服务端生成，不接受客户端伪造。现有待办的编辑、完成、重新打开和删除接口保持可用。

## 导入批次记录

每批记录时间、来源、分类理由及新增/重复/抑制/排除/待确认数量；历史导入另记实际覆盖范围。用户可以查看批次并撤销：撤销只移除该批新建、之后未被用户改动的条目，并放入回收站。后来写过笔记、完成、改变分类或恢复过的条目保留，显示冲突数量；补封面和自动 Qwen 分类不算用户改动。重复撤销不会再次删除内容。

网络或输入错误保留原数据；重新预览后可重试。批次撤销不会关闭网页、取消 B站收藏或删除任何源视频。每日采集沿用同一套预览、服务端复核、去重、回收站和撤销规则；已完成、已移除与手动改过的内容不会在次日被重置。GitHub 链接可快捷收录，真实 Codex / Git 项目续航见 [项目说明](project-resume.md)。自动采集 GitHub 收藏、跨来源控制台和 Obsidian 写入仍按 [日常自动化方案](daily-automation-proposal.md) 分阶段接入。
