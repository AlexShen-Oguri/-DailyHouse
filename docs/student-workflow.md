# 学生学习工作流

## 当前能力

`/workflow` 将课程、自学、科研和项目探索放在同一个手动工作流中：先记下来，决定是否值得投入，再留下可执行的下一步。原有待办继续安排具体行动，书架继续保存阅读材料，知识书屋继续只读浏览 Obsidian。

工作流提供本地分类建议、材料整理和 AI 提示词生成。提示词需要复制到用户选择的 AI 工具中使用；工作台没有接入模型 API，也不会仅凭链接生成内容摘要或论文结论。

## 从输入到行动

### 1. 随时快记

填写标题和可选链接，保存到「待整理」。暂时只记一个问题或念头也可以，不必先写完整计划。链接与标题关键词会给出可修改的类型、方向建议。

| 维度 | 可选值 | 用途 |
| --- | --- | --- |
| 类型 | 灵感、视频、论文、课程、项目、文章 | 决定这条内容如何处理，以及提示词采用哪一种引导方式。 |
| 方向 | 课内学习（含通识）、AI / 机器学习、软件开发、游戏设计、量化、科研、待定 | 帮助区分当前重点与候选探索，不把所有输入排到今天。 |

建议来自本地规则，并不意味着 AI 已阅读材料。用户可以随时修改；资料涉及多个方向时，先选对当前问题最有用的一个方向。

### 2. 整理与取舍

工作流按方向、状态和关键词筛选。状态由用户决定：

| 状态 | 适合何时使用 |
| --- | --- |
| 待整理 `inbox` | 刚记下，还没有决定用途。 |
| 进行中 `active` | 已确定当前问题，准备在近期投入时间。 |
| 暂存 `parked` | 仍有价值，但现在没有时间或缺少前置知识。 |
| 已完成 `done` | 这次想解决的问题已经处理；不代表掌握了整个领域。 |
| 已归档 `archived` | 退出日常关注，保留记录以便以后查找。 |

暂存、已完成和归档条目都可以通过改变状态恢复。工作流没有永久删除入口，也没有自动过期或清理机制；这些状态与书架移除及未来回收站方案不同。

每条记录可保存「想弄懂 / 解决的问题」「下次继续位置」「原文片段 / 字幕 / 作业要求」「笔记」和「下一步」。继续位置可写视频时间点、论文章节、课程练习或项目阻塞点；不会自动读取播放进度或 Git 状态。

### 3. 从书架接过来

通过工作流中的导入入口选择已有手动书架条目。一次导入保存书架条目 ID 和当时内容；同一书架记录重复导入会返回已有工作流记录，不覆盖之后的编辑。日报来源不包含在此入口。

导入后，两处笔记和状态独立保存：在工作流标为已完成，不会自动完成书架记录；编辑书架也不会覆盖工作流的问题、笔记或下一步。书架适合收藏，工作流适合处理当下问题。

### 4. 准备 AI 提示词

选择一条材料，补充问题和必要上下文，再生成提示词。界面语言决定提示词使用中文还是英文，个人内容保留原文。提示词可以复制到 AI 工具；用户自行判断答案，并把有用内容写回笔记和下一步。

| 场景 | 推荐补充的材料 | 希望 AI 帮助完成的工作 |
| --- | --- | --- |
| 课程 / 通识 | 作业要求、课程主题、已经尝试的解法 | 拆解要求，解释卡点，用问题检查理解，提出一次可执行练习。 |
| AI / ML 自学 | 当前问题、基础、教程片段或实验结果 | 补充必要先修知识，将一个概念落实为小实验。 |
| SWE / 游戏 / Quant 项目 | 目标、限制、当前问题、已经尝试的做法 | 缩小范围，设计最小验证，写清下一步与验收依据。 |
| 视频 | 想解决的问题、续看位置、有用的字幕或个人笔记 | 判断哪些片段值得继续，从已有材料整理可实践的收获。 |
| 论文 | 页码 / 章节、原文片段、术语或公式、具体困惑 | 先辨认研究问题与必要前置知识，再逐段解释，区分作者主张与推断，最后自测。 |
| 碎片灵感 | 想解决的问题、面向谁、可以投入的时间 | 将想法缩成一个可检验的小实验，再决定是否投入成项目。 |

论文和视频的链接用于保留来源，工作台不会自动读取正文、PDF 或字幕。精读前需要用户提供相关片段与出处；缺材料时先补材料，不把未知内容当成已经阅读。AI 的回答也不会自动写入工作流。

### 5. 下一步进入待办

把行动写成能直接开始的句子，例如「用一个小样本检查损失函数的梯度」或「列出论文实验中的三个比较条件」。选择计划日期后，主动将下一步加入待办；日期可以不填。

界面先保存当前表单，再请求创建待办；待办与它的工作流关联在一次原子写入中保存。反复点击不会重复创建同一行动，已关联待办可在待办页查看。前一个关联待办完成后，修改下一步可以继续创建新的关联待办；原来已完成的任务保留。待办完成不会自动把材料、课程或整个项目标记完成。

### 6. 留下可以继续的记录

每次收工补充三件事：做到了哪里，仍然卡在哪里，下次第一步是什么。可以只看解决当前问题所需的视频片段，也可以只精读论文的一节。完成状态由用户判断，不按观看时长、收藏量或代码提交数量计算掌握程度。

记录可复制为 Markdown，再由用户手动保存到笔记工具。工作台不会自动写入 Obsidian 或改动原材料。

## 每日与每周节奏

这些是页面内的安排建议，不会创建提醒、后台任务或自动更改待办日期。

| 时机 | 建议动作 |
| --- | --- |
| 每天开工 | 先看课程截止事项和日历，再挑一个学习 / 科研重点和一个项目小动作。忙碌时按实际精力减少。 |
| 学习或浏览途中 | 把问题、视频、论文和灵感放入待整理；有明确用途时再设为进行中。 |
| 一段工作结束 | 记录收获和继续位置，只给下一次留下一个可以开始的动作。 |
| 每周整理 | 回看待整理、进行中和暂存内容，选择一个主探索方向及一个轻量实验，其他保留或归档。此数量是建议，不是限制。 |

「每周整理提示词」将当前全库记录组成快照，包含当前状态、问题和下一步，用于帮助做取舍。它不是按本周事件生成的进度报告，不能据此声称哪些事项在本周完成、花了多少时间或学会了哪些技能。

| 能力 | 状态 | 实际边界 |
| --- | --- | --- |
| 标题 / 链接建议类型和方向 | 已实现 | 本地规则，可修改；不会调用模型或读取链接正文。 |
| 工作流持久化、筛选与恢复归档 | 已实现 | 保存到本机个人数据文件；恢复通过修改状态，没有永久删除。 |
| 手动书架条目导入与去重 | 已实现 | 用户选择后导入，按书架条目 ID 保留一次关联；不是持续同步。 |
| 下一步转待办 | 已实现 | 用户触发、原子保存、幂等关联；旧任务完成后可以安排新的下一步。 |
| 材料提示词与周复盘提示词 | 已实现 | 本地生成中英提示词；周复盘读取当前全库快照。 |
| 复制提示词与 Markdown | 已实现 | 用户粘贴到选定工具，工作台不代为发送或写入。 |
| 提供论文原文、字幕、作业要求 | 需手工 | 当前不抓取或转录内容；来源不足时无法可靠精读。 |
| 选择重点、决定完成、保存 AI 收获 | 需手工 | 分类、状态和建议都不能替代用户的判断。 |
| B站 / YouTube 历史或播放位置读取 | 后续能力，未实现 | 需要单独确定来源、授权和失败处理，不能承诺持续后台同步。 |
| 内置模型对话与自动内容分析 | 后续能力，未实现 | 需要另行配置模型服务和发送范围；当前选择的是提示词方式。 |
| 项目目录绑定、Git 快照与交接文件 | 后续能力，未实现 | 当前只有手动项目记录；不扫描目录或执行项目命令。 |
| 自动写入 Obsidian、来源批次及回收站 | 后续能力，未实现 | 需另外设计目标范围、预览、去重与恢复。 |
| 后台调度与自动导入 | 后续能力，未实现 | 本工作流没有建立新的定时任务，已有日报发现机制照常。 |

更广泛的来源集成设计保留在 [日常自动化方案](daily-automation-proposal.md)。学习进度小卡和桌面拾遗已取消，不在本功能或后续排期中。

## 数据与界面约定

工作流与待办、书架共用 `backend/data/personal-workbench.json`，个人材料、提示词内容和配置不进入代码仓库。应用只监听本机，新增页面沿用像素小院、中英界面、日夜主题、键盘操作、减少动态效果和响应式布局。来源关联与材料内容分开保存，不能把未连接、未读取或未分析的状态描述成成功。

编辑区有未保存提示；切换条目或通过站内链接离开时，可继续编辑或明确放弃。浏览器允许会话存储时，草稿与当前选择临时保留在该标签页的 `sessionStorage`，返回后可恢复，保存或明确放弃后清除。草稿不是正式备份；关闭标签页或清理浏览器数据前应保存。若服务端条目已变更，不用旧草稿覆盖新记录。
