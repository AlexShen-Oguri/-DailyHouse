# DailyHouse 日常自动化方案

**状态：书架闭环、快捷导入、本机 Qwen 分类、180 天只读日历、每日采集调度、灵感对话与真实项目续航已实现，后续来源联动仍分阶段推进。** 当前书架已有十类主题、完成归档、30 天回收站、来源防重入、B站历史 JSON 预览 / 提交、批次日志 / 撤销，以及本机导入 CLI；视频、文章、书籍、教程和 GitHub 均可通过批量链接或本机文件选择器手动收录，分类失败可重试、低置信可确认。Codex 当前任务的「每日小院采集」已设为 ACTIVE，每天纽约时间 **09:45** 运行；运行条件、实际覆盖和故障处理见 [每日采集说明](daily-collection.md)。真实 Codex 项目、只读 Git 状态、GitHub 仓库关联与独立立项已接通，详见 [项目续航](project-resume.md)。统一来源控制台、跨来源收件箱、Obsidian 写入和 Issue / PR 采集尚未实现。启用调度不表示未来一次采集已执行成功，也不代表尚未配置的账号或来源已连接。

书架现有闭环的具体输入、命令和恢复规则见 [书架导入说明](reading-import.md)。页面以「未完成 / 已完成」为主状态，一排紧凑入口选择媒介类型，主题分类与进行状态另行筛选。新完成动作记录真实完成时间；缺少时间的旧记录不补造。完成日期筛选仍未实现。书架、灵感与项目均有各自的回收站、恢复和永久删除；批次撤销仍只覆盖书架，不是通用版本回滚。

目标是每天把值得处理的信息送到合适的位置，并让它们有明确的出口。首期围绕「今天要做什么、接着做哪个项目、待看什么、看完留下什么」组织，不扩大连接器数量。桌面拾遗退出产品，学习进度小卡取消；独立学习工作流已撤销，不作为现有能力继续扩展。灵感库包含碎片记录、融合、本机 Qwen 持续对话和独立确认立项，使用说明见 [碎片想法与时间线](ideas.md)及[本机 AI](local-ai.md)；真实项目续航另见 [使用说明](project-resume.md)；每日采集不会自动生成灵感、待办或启动项目。

## 1. 哪些来源适合自动化

| 来源 | 可读取的内容与方式 | 前置条件、边界与建议 |
| --- | --- | --- |
| 既有科技、审美日报 | 本地脚本发现新 PDF，读取类型、日期、文件指纹；以后可附生成流程提供的摘要 | 固定输出目录与正式文件命名。沿用现有 09:00 制作流程，确认产出完成后入架，不重新建立一套报告生成器。 |
| Obsidian | 直接读取指定 vault 的 Markdown、属性、链接和修改信息；官方 CLI 可搜索、列任务、读取笔记 | 指定 vault 与允许索引的子目录。直接读文件最少依赖；官方 CLI 需要启用功能、合适的安装包版本及运行中的 Obsidian。不得把整个 vault 自动变成待办。 |
| 本地 Git 项目 | `git status --porcelain=v2 --branch`、`git log` 读取分支、最近提交、改动状态 | 只读已绑定项目。未 fetch 时，上游差异只代表本地缓存；分别标注本地检查与远端更新时间，不据提交数量推断完成率。 |
| GitHub | 官方 `gh` / API 读取收藏仓库、选定项目的 Issue、PR 和状态 | 独立配置账号授权和仓库范围。首次预览历史范围，默认建立基线，再导入后续新增；不把全部收藏直接变成今日任务。 |
| Google / Apple Calendar | 已支持 Google Calendar iCal 地址、已有 iCloud 订阅和本地 `.ics`；读取今天起 180 天，可按月份查看 | Windows 优先 Google Calendar，Mac 保留 Apple Calendar。Google 可用其 iCal 私密地址；地址只保存在本机，不通过设置接口返回。现有本地文件继续可用，但文件快照不会自行更新。日历只读，不修改源事件。 |
| Bilibili | 每日 09:45 的采集任务通过已登录浏览器页面读取观看历史、当前播放位置、标题、链接和可见封面，再使用本机 CLI 导入 | 已启用浏览器辅助的条件式同步。电脑须开机、Codex 须运行且 B站已登录；页面结构或验证变化会中断。不能称为稳定的官方历史 CLI，也不能绕过平台验证。 |
| Chase | 用户导出的 CSV 放入指定目录后，脚本解析并增量导入 | 获取 CSV 仍是手动步骤。完整银行同步要另行选择可用的授权聚合服务；其他应用的既有绑定不能直接移植到本网站。 |
| Codex 对话 | 任务执行时，可用已授权的任务读取能力补充项目上下文 | 不把某个应用内部历史文件当作稳定 CLI 接口。当前通过本机 Codex app-server 读取项目、对话和可用的最近一轮摘要；接口不支持时降级显示明确标注的对话预览，Git 状态仍可单独读取。 |

依据：Obsidian 的 vault 是普通本地 Markdown 文件夹，[存储说明](https://help.obsidian.md/Files+and+folders/How+Obsidian+stores+data)；其 [CLI 文档](https://help.obsidian.md/cli) 当前要求 1.12.7+ 安装包并依赖应用运行。Git 提供适合脚本解析的 [porcelain 状态](https://git-scm.com/docs/git-status)；GitHub 提供 [CLI API](https://cli.github.com/manual/gh_api)、[收藏仓库接口](https://docs.github.com/en/rest/activity/starring#list-repositories-starred-by-the-authenticated-user)和 [PR JSON 输出](https://cli.github.com/manual/gh_pr_list)。Google 官方说明了 [iCal 私密地址](https://support.google.com/calendar/answer/37648)和[导出 ICS](https://support.google.com/calendar/answer/37111)。Apple 的[共享规则](https://support.apple.com/guide/icloud/mm6b1a9479/icloud)与[第三方授权说明](https://support.apple.com/121539)不能等同于本网站已取得账户级授权。B站能力以[官方开放平台](https://open.bilibili.com/doc)为边界。Chase 支持[桌面导出 CSV](https://www.chase.com/personal/financial-tools/build/spending-budget)，其[数据共享 API 示例](https://apidemo.chase.com/)面向已有合作关系的开发者。

## 2. 目标：让各来源共享完整生命周期

下面描述跨来源目标。书架范围的预览、收录、完成、移除恢复和批次记录已实现；灵感与真实项目也已有各自的删除恢复流程。下图仍是跨来源目标，不表示统一收件箱或全部联动已经接通。

```text
读取来源 → 校验和去重 → 收件箱 → 待读 / 今日待办 / 项目
                         ↓             ↓
                      忽略规则      使用、修改、关联
                                       ↓
                                已完成资料库 / 项目归档
                                       ↓
                                可选 Obsidian 笔记

任意本地条目 → 移除 → 30 天回收站 → 恢复或到期清理
                         └→ 保留最小来源抑制记录，避免再次导入
```

未来统一收件箱用于决定是否值得加入，不是第二个无限书架。当前书架以导入预览和批次中的待确认记录承担人工审阅，不另建跨来源收件箱。确定性来源可以设置自动接收：例如正式日报、明确选定的 GitHub 仓库；主题不明确的 B站视频先给出标题、封面、理由供批量接受或忽略。来源可设置每日上限，超额内容留在收件箱，不不断推高今日待办。当前书架记录无需重新审核或丢失已有状态。

每条记录保留来源 ID、规范链接、首次发现、最近成功读取、导入批次、来源时间和用户操作时间。去重不能只比较标题：视频使用 BV 等平台身份，课程的分集另存；GitHub 使用仓库/Issue/PR ID；日报使用类型与刊期，并单独记录文件版本；手动条目使用本地 ID。一个内容出现在多个来源时合并来源证据，保留用户标题、备注和状态。

当前书架每批记录新增、重复、抑制、排除和待确认数量，保存逐项理由及实际覆盖范围。同源重复导入不会覆盖用户标题、笔记、分类或完成状态。批次撤销仅撤回该批新建且之后未被用户修改的条目，移入书架回收站；后续编辑、完成或恢复过的内容保留并报告冲突，补封面不算用户修改，重复撤销不重复移除。

未来其他来源的更新型导入还需区分新增与更新，失败只重试未完成部分；更新撤销必须检测后续用户修改，不能把当前只处理新增条目的批次能力当作通用版本回滚。

移除、归档和完成不同：完成表示已处理，未来项目归档表示退出活跃视图，移除进入对应回收站。当前书架单项、批量和全部移除均显示具体范围；筛选后的全选与整个书架清空分别表达。恢复保留原 ID、阅读状态、分类、笔记、封面与已知完成时间；30 天内可单项或批量恢复，到期不可恢复，后续操作清理完整快照并保留最小来源抑制键。书架、灵感与项目回收站现在均提供单条永久删除确认；网站操作不删除外部源内容。显式手动重新收藏可以解除抑制，但会建立新记录；若要原笔记与 ID，应使用恢复。恢复遇到已重新收藏的同源记录时提示冲突。旧版本永久移除且没有快照的内容不能假装可找回。来源重复出现或重试，不能让用户移除的内容自动复活。

本网站移除只改变本地收藏，不删除 B站视频、GitHub 仓库、日历事件或原始 PDF。断开来源停止取数，已有记录保留；另设明确的本地清理入口。来源失效、空结果或权限不足不等同于用户删除。

## 3. 视频、教程和报告看完之后

当前待读书架的日常视图只留待开始与进行中，已完成有独立主入口。一排紧凑类型入口包含全部、书籍、视频、课程 / 教程、GitHub、文章、科技早报、审美图鉴；搜索与主题分类位于次层。十类主题为编程 / AI、科技、设计、自然科学、人文社科、语言、商业 / 经济、效率 / 职业、生活技能、其他 / 待分类，导入后可修正。旧 `programming`、`ai` 兼容显示为 `programming_ai`，不改写个人笔记、状态或旧批次撤销指纹。配套编辑、单项 / 批量 / 全部移除及回收站恢复。视频块展示已有封面；缺失或加载失败时保留原有书签和文字，不能影响标题、状态和操作。封面来自来源元数据，不为填满页面下载视频。

当前 B站候选规则是最近 **7 × 24 小时**、已知播放比例严格低于 **25%**，范围扩大为教育或实用内容，覆盖上述十类主题。编程课程与 AI 实践归「编程 / AI」，科技资讯、产品技术与新功能归「科技」，不因是新闻就一律待审；推广、夸张宣传或学习价值不明确的标题仍待确认。明显的纯娱乐排除，进度未知不能当作 0%。候选资格先使用本地规则筛选，入架后由本机 Qwen 按标题、链接与备注分类；手动分类优先，不表示模型已看过视频。多 P 记录保留具体分集观看证据，同一 BV 按来源身份去重，当前分集位置不代表整套课程完成率。

浏览器实际观察到的条目整理为 JSON 后，可在网页或 CLI 中预览。用户可以显式接受主题待确认项或排除候选；改变选择后更新预览，再确认写入，服务端提交时重查当前时间、重复和抑制记录。待确认项可只存入批次记录并稍后重新审阅，不进入待读。用户选择不能绕过时间、未知或过高进度、明确娱乐、重复、曾移除来源等规则。

每批保存实际覆盖范围及是否读完整；不完整结果有明确提示，不能声称整个窗口已经同步完成。每日任务已负责触发浏览器采集，登录失效或页面变化时跳过该来源并记录原因；下一次重读最近一周以补漏，再按来源身份去重。当前没有常驻的历史接口采集器或持久同步游标，不保证补回一周窗口之外的遗漏；恢复后的人工补读与未来游标机制仍需另行实现。

用户标记完成后，保存成功再播放打勾与淡出动画，条目保留在「已完成」入口。当前可按类型、主题及文字搜索，支持重新开始、补充笔记和移除，保留原链接与封面。新完成动作记录并展示完成日期；缺少可靠时间的旧记录不推算历史日期。按完成日期筛选和关联项目仍待后续实现。完成后不强制弹出总结表单，也不自动宣称学会了某项技能。

**手动完成优先于来源播放位置。** 之后取到低播放进度，不得把已完成内容重新放回待读。播放进度只是观看证据，不代表理解程度；多 P 视频当前分集播放完毕也不代表课程完成。课程可保留「看到第几节」备注，首期不增加学习进度小卡。

未来需要沉淀时，可另行实现「保存到 Obsidian」：预览笔记标题、源链接、个人心得、关联项目与完成日期，然后写入选定目录。用稳定记录 ID 关联已创建笔记，重复点击打开已有笔记；后续同步不覆盖手写正文。没有笔记也能完成，单纯看过的资料保存在资料库即可。

日报当前同样进入待读和已完成视图。报告文件更新时保留阅读状态，提示「内容有更新」，由用户决定重读。日期取正式刊期语义，不用文件修改日期冒充。后续还需为文件移动或不可用提供明确的路径修复入口，并保留此前阅读记录。

报告生产端宜先写临时文件，验证 PDF 后原子改名，并写入完成清单（类型、刊期、版本指纹、文件位置）；导入端只接收完成产物。过渡期没有完成清单时，检查 PDF 文件头、文件大小稳定与可读取性，仍标明校验范围。当前单纯发现非空正式 PDF 的机制需要在此阶段升级，不能把半成品的存在当成制作成功。

## 4. 项目续航完整流程

当前已读取真实 Codex 工作目录、最近一轮对话、Git 分支/未提交文件数/最近提交和匹配的 GitHub 仓库；可回到 Codex 对话，网站入口支持移除、恢复和永久删除。独立立项会创建专属目录、私有仓库与 Codex 工作，并交接完整灵感上下文，详见 [项目续航](project-resume.md)。下面保留更完整的后续目标：结构化下一步同步、Issue / PR 联动、日常交接草稿、路径修复与高级状态管理尚未全部实现；不把真实 Git 事实推算成完成率。

| 环节 | 当前基础之上的完整目标（具体已实现边界见项目续航说明） |
| --- | --- |
| 绑定 | 选择项目目录、显示名称、目标和状态/交接文件；可选关联 GitHub 仓库与 Obsidian 笔记。预览实际读取范围后保存，不全盘扫描。 |
| 采集 | 只读 Git 状态、最近提交和明确选择的结构化状态。优先使用任务 ID、标题、状态、下一步、阻塞项和 `updatedAt`；缺失显示未提供，不从 README 词句猜进度。 |
| 时间与冲突 | 分开显示来源记录时间、文件修改时间、本次读取时间。文档与 JSON 矛盾时保留各自出处；失败时标记上次成功快照，不伪装为实时。 |
| 继续入口 | 打开项目目录、原有编辑入口、交接文档、相关 Issue/PR、关联书架资料；只打开明确目标，不从文档抽取命令执行。 |
| 下一步变待办 | 先允许编辑标题，确认后关联现有待办系统。项目 ID 加来源任务 ID 去重；没有 ID 时用稳定映射。重复点击跳转原待办，刷新或文字小改不会重复创建。 |
| 日常收工 | 用户用简短交接记录「做到哪里、下一步、阻塞、相关文件/链接」。可由本次 Git 事实生成草稿，用户补充意图；写源文件需预览，不静默覆盖既有交接。 |
| 状态管理 | 活跃、暂停、阻塞、完成归档均可修改；阻塞标明原因，暂停不持续催办。项目完成进入归档，可检索成果、重开或移除。 |
| 移除与修复 | 移除项目卡进 30 天回收站，不删除磁盘目录、仓库和笔记。目录移走保留项目身份，重新选择路径修复绑定；不能把临时不可读视为项目消失。 |

待办完成不自动等同于项目完成；项目下一步在源文件仍未更新时，显示「此项已完成，待更新下一步」，不得重新生成。源内容变化也不能静默改掉用户待办。日常取数不自动 fetch/pull、切分支、commit、push、安装依赖或启动开发服务器；这些属于明确的项目操作，不是续航采集。

## 5. 其他来源各自的闭环

以下新增联动、写入、修复和来源管理仍待实现；当前已实现的只读日历、Obsidian 预览与日报发现继续可用。日历已扩展为今天起 180 天，支持月份切换、读取范围与更新时间；取消原先 31 天的截断，不再静默只取前 1000 个事件。Google / iCloud 在线订阅和本地导出文件都适用，超出容量限制时明确报错。

**日历与今日待办。** 当前日程和行动分开显示，Windows 优先连接 Google Calendar，Mac 保留 Apple Calendar。已支持读取时区、夏令时、全天事件、循环例外及改期，取消实例不出现在当前日程中；每日任务刷新已配置来源，本地 ICS 仍需先更新文件。后续可允许用户把某个日程关联准备任务，并提供取消说明、本地隐藏与恢复；这些联动尚未实现，不把所有会议每天复制成待办。只读事件的修改仍回到日历来源。

**Obsidian。** 知识书屋索引已指定目录的标题、属性、路径和链接，支持搜索、预览、打开原笔记；索引更新不改正文。来源移动、重命名和删除可修复关联，断开后清除索引的选择需明确，不删除源文件。可选的资料笔记写入采用独立目录、预览与稳定 ID；写失败可重试，文件已存在先核对，不自动覆盖。笔记任务只有明确选择才加入今日待办。

**GitHub。** 首次列出将导入的收藏和项目范围，确认从什么时间开始。兴趣仓库进收件箱/书架，自己项目的 Issue/PR 变化进对应项目续航，不混成一套待办。支持按仓库暂停、忽略、取消本地关联、打开源页面；远端关闭/合并只更新来源事实，不替用户完成本地行动。

**Chase。** 文件入箱后先预览日期、账号别名、币种、行数及异常，核对后入账。去重优先可靠交易 ID；CSV 缺少 ID 时比较账户、日期、金额、描述及批次，疑似重复进入核对，不强删同日同额消费。pending 转 posted 要替换关联而非算两笔；转账两端不重复计入收支，退款关联原交易并处理部分退款。配套分类修改、拆分、排除、对账、月度归档、导出与整批撤销；不显示推算出来的「实时余额」。只有用户导出的文件到达后，这一段才自动进行。

## 6. 每日节奏与运行保障

以下时间以 `America/New_York` 为准；09:45 的采集已启用，其他建议明确列出状态：

| 时机 | 状态与流程 |
| --- | --- |
| 09:00 | 既有科技与审美报告开始制作，保持原有生成任务；不另建报告生成器。 |
| 09:45 | **已启用「每日小院采集」Codex heartbeat。** 检查本机服务、发现正式日报、刷新已配置日历，再通过登录浏览器读取最近 7 × 24 小时 B站历史并预览、导入。电脑须开机、Codex 须运行，B站需登录；某一来源失败不清空已有内容，也不阻止其他可用来源。 |
| 报告产出后 | 现有书架发现正式文件；未来升级为生产端完成清单与完整 PDF 校验。到了制作时间不等于报告已经成功产出。 |
| 未来可选 08:45 | 读取绑定项目、扩展 Obsidian 索引与 GitHub，整理来源异常；这部分尚未启用，不是现有采集任务的隐藏职责。 |
| 每次收工 | 当前可手动补充想法或项目记录；基于真实 Git 状态的交接草稿和晚间快照仍是方案，不自动把当日未完成任务全部顺延。 |

当前只有「每日小院采集」负责每天的导入触发，既有报告任务独立负责产物。修改时间或暂停时更新已有任务，不再创建第二个调度器。失败后的下一次重读最近一周，依靠规范来源身份避免重复与复活；相同待确认候选不每天制造空批次。统一来源运行锁、幂等运行 ID、持久游标及任意时间段补跑仍是后续增强，不能把一周内重叠读取当成无限历史补齐。

执行 CLI 脚本与管理定时任务是两层能力：本轮已通过 Codex 调度管理启用当前任务的每日 heartbeat，CLI 负责实际导入。需要本机文件和浏览器的执行仍要求电脑开机、Codex 运行及登录有效；单独打开网页不会启动 Codex 调度。运行日志记录尝试时间、实际覆盖、结果和错误，不用 ACTIVE 状态冒充每次成功。参见[官方定时任务说明](https://learn.chatgpt.com/docs/automations?surface=app)。

本地任务只能在电脑可执行时运行，浏览器读取还依赖可用会话。未来若改用 Windows 调度，可利用[错过时间后补跑](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-startwhenavailable)和[睡眠唤醒](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-waketorun)；完全关机无法按时执行。当前没有额外 Windows 定时器，也没有云端访问本机文件的通道。待补跑状态面板属于后续来源控制台范围。

现有书架 CLI `scripts/reading-import.mjs` 已提供 `preview`、`apply`、`history`、`undo` 四个命令，只访问本机工作台 API，不直接编辑个人 JSON；调用格式见 [书架导入说明](reading-import.md)。提交重新检查当前记录和时间窗口，撤销检查后续用户修改。个人输入、日志与记录不进入源码仓库。

未来多个来源并行写入时还需统一调度锁、写入队列与版本检查，并为失败部分提供重试和恢复点。当前本机导入命令不等于这些后台运行保障已经全部实现。

未来来源控制台须提供：配置与覆盖范围、最近尝试/成功时间、下次计划、待确认数量、失败原因、手动同步、仅重试失败部分、暂停、恢复、断开和本地清理。当前先使用 Codex 调度状态、书架批次和本机 `.runtime` 日志；有有意义的新增、失败或需要登录时通知，无变化和同一未解决问题保持安静。
