# DailyHouse 日常自动化方案

**状态：广泛来源接入仍是待选择的方案。** 已授权并实现的学习工作流见 [学生学习工作流](student-workflow.md)：手动快记、方向整理、继续位置、下一步关联待办、从手动书架条目导入、AI 提示词及 Markdown 复制。其待整理列表只接收用户保存或选择的内容，不会自动读取外部历史。本文提出的外部来源自动导入、跨来源统一收件箱、通用回收站、来源控制台、项目目录绑定与 Git 快照仍未实现，也未创建或启用新的定时任务。本文不代表任何个人来源已配置、账号已授权或同步已验证。

当前已完成内容可在书架的「已完成」筛选回看或重新开始；当前书架移除不可撤销，仅日报已有防止再次收录的隐藏记录。学习工作流通过调整状态恢复归档条目，不提供永久删除，也不是书架回收站。下文的通用来源抑制、30 天回收站、完成日期检索和批次撤销都是拟新增能力；既有视频封面和桌面拾遗移除保持不变。

目标是每天把值得处理的信息送到合适的位置，并让它们有明确的出口。已落地的学习工作流先连接「收集、取舍、动手、留下收获」；下文是未来扩展来源时的设计约束，不是当前页面的功能清单。桌面拾遗退出产品，学习进度小卡取消；已有学习提醒继续保留，不因取消小卡而停用。

## 1. 哪些来源适合自动化

| 来源 | 可读取的内容与方式 | 前置条件、边界与建议 |
| --- | --- | --- |
| 既有科技、审美日报 | 本地脚本发现新 PDF，读取类型、日期、文件指纹；以后可附生成流程提供的摘要 | 固定输出目录与正式文件命名。沿用现有 09:00 制作流程，确认产出完成后入架，不重新建立一套报告生成器。 |
| Obsidian | 直接读取指定 vault 的 Markdown、属性、链接和修改信息；官方 CLI 可搜索、列任务、读取笔记 | 指定 vault 与允许索引的子目录。直接读文件最少依赖；官方 CLI 需要启用功能、合适的安装包版本及运行中的 Obsidian。不得把整个 vault 自动变成待办。 |
| 本地 Git 项目 | `git status --porcelain=v2 --branch`、`git log` 读取分支、最近提交、改动状态 | 只读已绑定项目。未 fetch 时，上游差异只代表本地缓存；分别标注本地检查与远端更新时间，不据提交数量推断完成率。 |
| GitHub | 官方 `gh` / API 读取收藏仓库、选定项目的 Issue、PR 和状态 | 独立配置账号授权和仓库范围。首次预览历史范围，默认建立基线，再导入后续新增；不把全部收藏直接变成今日任务。 |
| Apple Calendar | 在线 ICS 订阅可定时读取；本地 `.ics` 可读取导出快照 | 本地文件不会自行更新。公共订阅链接持有者可读，不能默认公开主日历；专用日历订阅或未来独立授权的私有接入需明确选择。首期只读。 |
| Bilibili | 已登录浏览器页面提供观看历史、当前播放位置、标题、链接和可见封面 | 属于浏览器辅助的条件式同步。官方开放平台未查到可据此承诺的个人历史/进度接口；登录、页面结构或验证变化会中断。不能称为稳定的官方 CLI 全自动导入。 |
| Chase | 用户导出的 CSV 放入指定目录后，脚本解析并增量导入 | 获取 CSV 仍是手动步骤。完整银行同步要另行选择可用的授权聚合服务；其他应用的既有绑定不能直接移植到本网站。 |
| Codex 对话 | 任务执行时，可用已授权的任务读取能力补充项目上下文 | 不把某个应用内部历史文件当作稳定 CLI 接口。首期续航以 Git 事实、结构化状态和交接笔记为基础，对话不是必需依赖。 |

依据：Obsidian 的 vault 是普通本地 Markdown 文件夹，[存储说明](https://help.obsidian.md/Files+and+folders/How+Obsidian+stores+data)；其 [CLI 文档](https://help.obsidian.md/cli) 当前要求 1.12.7+ 安装包并依赖应用运行。Git 提供适合脚本解析的 [porcelain 状态](https://git-scm.com/docs/git-status)；GitHub 提供 [CLI API](https://cli.github.com/manual/gh_api)、[收藏仓库接口](https://docs.github.com/en/rest/activity/starring#list-repositories-starred-by-the-authenticated-user)和 [PR JSON 输出](https://cli.github.com/manual/gh_pr_list)。Apple 的[共享规则](https://support.apple.com/guide/icloud/mm6b1a9479/icloud)与[第三方授权说明](https://support.apple.com/121539)不能等同于本网站已接入。B站能力以[官方开放平台](https://open.bilibili.com/doc)为边界。Chase 支持[桌面导出 CSV](https://www.chase.com/personal/financial-tools/build/spending-budget)，其[数据共享 API 示例](https://apidemo.chase.com/)面向已有合作关系的开发者。

## 2. 所有来源共用一个生命周期

```text
读取来源 → 校验和去重 → 收件箱 → 待读 / 今日待办 / 项目
                         ↓             ↓
                      忽略规则      使用、修改、关联
                                       ↓
                                已完成资料库 / 项目归档
                                       ↓
                                可选 Obsidian 笔记

任意本地条目 → 移除 → 30 天回收站 → 恢复或永久清除
                         └→ 保留最小来源抑制记录，避免再次导入
```

收件箱用于决定是否值得加入，不是第二个无限书架。确定性来源可以设置自动接收：例如正式日报、明确选定的 GitHub 仓库；主题不明确的 B站视频先给出标题、封面、理由供批量接受或忽略。来源可设置每日上限，超额内容留在收件箱，不不断推高今日待办。当前书架记录无需重新审核或丢失已有状态。

每条记录保留来源 ID、规范链接、首次发现、最近成功读取、导入批次、来源时间和用户操作时间。去重不能只比较标题：视频使用 BV 等平台身份，课程的分集另存；GitHub 使用仓库/Issue/PR ID；日报使用类型与刊期，并单独记录文件版本；手动条目使用本地 ID。一个内容出现在多个来源时合并来源证据，保留用户标题、备注和状态。

每次导入必须给出新增、更新、重复、已忽略和失败数量，并可查看批次。重跑同一批次不产生重复；失败只重试未完成部分。批次撤销撤回该批新增和未被用户进一步修改的更新；对之后写过备注、完成或关联项目的条目列出冲突，交由用户决定，不能静默覆盖后续工作。

移除、归档和完成不同：完成表示已处理，归档表示退出活跃视图，移除进入回收站。单项、批量和全部移除均显示具体范围；筛选后的全选与整个书架清空分别表达。回收站保存原状态和关联，30 天内可恢复；到期可清除正文与本地缩略图，保留最小来源抑制键。恢复或主动重新加入解除对应抑制；撤销一次「全部移除」可整批恢复。来源当天重复出现、文件改名或重试，不能让被移除内容复活。

本网站移除只改变本地收藏，不删除 B站视频、GitHub 仓库、日历事件或原始 PDF。断开来源停止取数，已有记录保留；另设明确的本地清理入口。来源失效、空结果或权限不足不等同于用户删除。

## 3. 视频、教程和报告看完之后

待读书架的日常视图只留待开始与进行中，配套搜索、类型/来源筛选、编辑、单项与批量移除。视频块展示已有封面；缺失或加载失败时保留原有书签和文字，不能影响标题、状态和操作。封面来自来源元数据，不为填满页面下载视频。

B站沿用近 14 天、已知播放比例严格低于 25%、编程/AI/设计专业知识的候选规则。进度未知不能当作 0%；多 P 记录要保留具体分集，不能用当前分集的位置推断整套课程。分类存下简短理由与证据，不确定的内容留给用户筛选。每次记录实际覆盖到哪一天、页面是否读完整；未覆盖窗口或中途失去登录时标记部分结果，不推进「已完整同步」游标。首次和后续增量都支持预览、批量接受/忽略、查看来源和重试。

用户标记完成后，保存成功再播放打勾与淡出动画，条目进入「已完成资料库」。资料库可按主题、来源、完成日期检索，支持重新开始、关联项目、补充笔记和移除。完成后不强制弹出总结表单，也不自动宣称学会了某项技能。

**手动完成优先于来源播放位置。** 之后取到低播放进度，不得把已完成内容重新放回待读。播放进度只是观看证据，不代表理解程度；多 P 视频当前分集播放完毕也不代表课程完成。课程可保留「看到第几节」备注，首期不增加学习进度小卡。

需要沉淀时，用户选择「保存到 Obsidian」：预览笔记标题、源链接、个人心得、关联项目与完成日期，然后写入选定目录。用稳定记录 ID 关联已创建笔记，重复点击打开已有笔记；后续同步不覆盖手写正文。没有笔记也能完成，单纯看过的资料保存在资料库即可。

日报同样进入待读和资料库。报告文件更新时保留阅读状态，提示「内容有更新」，由用户决定重读。文件移动或不可用显示修复入口，不把此前阅读记录删除；日期取正式刊期语义，不用文件修改日期冒充。

报告生产端宜先写临时文件，验证 PDF 后原子改名，并写入完成清单（类型、刊期、版本指纹、文件位置）；导入端只接收完成产物。过渡期没有完成清单时，检查 PDF 文件头、文件大小稳定与可读取性，仍标明校验范围。当前单纯发现非空正式 PDF 的机制需要在此阶段升级，不能把半成品的存在当成制作成功。

## 4. 项目目录与 Git 续航完整流程（待实施）

学习工作流已能手动记录项目问题、继续位置与下一步，并关联待办。以下的目录绑定、事实采集、源文件交接与回收站是额外的来源能力，未随学习工作流启用。

项目续航是「打开以后立刻知道下一步」，不靠一个自动推测的进度条。

| 环节 | 必须配套的行为 |
| --- | --- |
| 绑定 | 选择项目目录、显示名称、目标和状态/交接文件；可选关联 GitHub 仓库与 Obsidian 笔记。预览实际读取范围后保存，不全盘扫描。 |
| 采集 | 只读 Git 状态、最近提交和明确选择的结构化状态。优先使用任务 ID、标题、状态、下一步、阻塞项和 `updatedAt`；缺失显示未提供，不从 README 词句猜进度。 |
| 时间与冲突 | 分开显示来源记录时间、文件修改时间、本次读取时间。文档与 JSON 矛盾时保留各自出处；失败时标记上次成功快照，不伪装为实时。 |
| 继续入口 | 打开项目目录、原有编辑入口、交接文档、相关 Issue/PR、关联书架资料；只打开明确目标，不从文档抽取命令执行。 |
| 下一步变待办 | 先允许编辑标题，确认后关联现有待办系统。项目 ID 加来源任务 ID 去重；没有 ID 时用稳定映射。重复点击跳转原待办，刷新或文字小改不会重复创建。 |
| 日常收工 | 用户用简短交接记录「做到哪里、下一步、阻塞、相关文件/链接」。可由本次 Git 事实生成草稿，用户补充意图；写源文件需预览，不静默覆盖既有交接。 |
| 状态管理 | 活跃、暂停、阻塞、完成归档均可修改；阻塞标明原因，暂停不持续催办。项目完成进入归档，可检索成果、重开或移除。 |
| 移除与修复 | 移除项目卡进 30 天回收站，不删除磁盘目录、仓库和笔记。目录移走保留项目身份，重新选择路径修复绑定；不能把临时不可读视为项目消失。 |

待办完成不自动等同于项目完成；项目下一步在源文件仍未更新时，显示「此项已完成，待更新下一步」，不得重新生成。源内容变化也不能静默改掉用户待办。日常取数不自动 fetch/pull、切分支、commit、push、安装依赖或启动开发服务器；这些属于明确的项目操作，不是续航采集。

## 5. 其他来源各自的闭环

**日历与今日待办。** 日程和行动分开显示；用户可把某个日程关联一个准备任务，但不把所有会议每天复制成待办。日历同步按 UID 与循环实例身份去重，处理时区、夏令时、全天事件、循环例外、改期与取消。取消事件保留说明，关联任务不擅自删除。只读事件的修改回到日历来源；本地隐藏、取消隐藏不影响源日历。每次显示覆盖时间段和上次成功读取时间。

**Obsidian。** 知识书屋索引已指定目录的标题、属性、路径和链接，支持搜索、预览、打开原笔记；索引更新不改正文。来源移动、重命名和删除可修复关联，断开后清除索引的选择需明确，不删除源文件。可选的资料笔记写入采用独立目录、预览与稳定 ID；写失败可重试，文件已存在先核对，不自动覆盖。笔记任务只有明确选择才加入今日待办。

**GitHub。** 首次列出将导入的收藏和项目范围，确认从什么时间开始。兴趣仓库进收件箱/书架，自己项目的 Issue/PR 变化进对应项目续航，不混成一套待办。支持按仓库暂停、忽略、取消本地关联、打开源页面；远端关闭/合并只更新来源事实，不替用户完成本地行动。

**Chase。** 文件入箱后先预览日期、账号别名、币种、行数及异常，核对后入账。去重优先可靠交易 ID；CSV 缺少 ID 时比较账户、日期、金额、描述及批次，疑似重复进入核对，不强删同日同额消费。pending 转 posted 要替换关联而非算两笔；转账两端不重复计入收支，退款关联原交易并处理部分退款。配套分类修改、拆分、排除、对账、月度归档、导出与整批撤销；不显示推算出来的「实时余额」。只有用户导出的文件到达后，这一段才自动进行。

## 6. 建议的每日节奏与运行保障

以下时间以 `America/New_York` 为准，**是建议，尚未启用**：

| 时机 | 建议流程 |
| --- | --- |
| 08:45 | 读取本机项目、Obsidian 索引、已配置日历及 GitHub；整理新内容和需要处理的来源异常。 |
| 09:00 | 既有科技与审美报告开始制作，保持原有生成任务。 |
| 报告产出后 | 以完成标记或完整文件落盘为依据导入；未完成时等待，不能因为到了 09:00 就报告成功。 |
| B站具备登录条件时 | 每日增量查看近期窗口，重叠回看用于弥补漏读；低于 25% 等规则只决定候选资格。会话失效则暂停该来源，其他来源照常。 |
| 每次收工 | 更新项目交接；晚上可保存最后一次只读项目快照，不自动把当日未完成任务全部顺延。 |

只有一个导入调度器负责触发与补跑，既有报告生成任务继续独立负责产物。不要同时让浏览器轮询、应用启动任务和另一个系统定时器各自执行同一批导入。统一运行锁、幂等批次 ID 和来源游标；来源成功提交后才推进游标，断网或关机后补上遗漏，而不是重建所有条目。

执行 CLI 脚本与管理定时任务是两层能力。若选择现有桌面应用的定时功能，需要本机文件的任务要求电脑开机、应用运行；网页任务不能直接操作本机目录，Codex CLI 本身也没有 Scheduled 管理界面。实施时通过应用提供的调度管理建立唯一任务，不能把「命令可运行」当作「已每天自动运行」。参见[官方定时任务说明](https://learn.chatgpt.com/docs/automations?surface=app)。

本地任务只能在电脑可执行时运行，浏览器读取还依赖可用会话。未来若选 Windows 调度，可利用[错过时间后补跑](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-startwhenavailable)和[睡眠唤醒](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-waketorun)；完全关机无法按时执行。云任务也不能自动访问本机文件。界面显示「待补跑」而非虚报按时成功。

所有写入经过后端 API，CLI 只提交经过校验的导入请求，不直接编辑个人 JSON。后端使用单写入队列、原子保存和版本检查，避免导入与用户同时修改相互覆盖。失败批次保存必要的本地日志和恢复点，个人内容、凭据与日志不进入代码仓库。本文没有定义或声称任何新的导入 CLI 命令已存在。

来源控制台必须同时提供：配置与覆盖范围、最近尝试/成功时间、下次计划、待确认数量、失败原因、手动同步、仅重试失败部分、暂停、恢复、断开和本地清理。状态区分未配置、正常、等待产物、需登录、离线、部分失败；单一来源失败不阻塞全局。通知只在有值得处理的新增、持续失败或需要用户操作时出现。

## 7. 按完整功能包分期交付

| 阶段 | 一次交付的范围 | 必须通过的验收 |
