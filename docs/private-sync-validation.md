## 覆盖的行为

- 两台授权设备增改删、断网后重试、重复请求和同时修改；本机及云端版本保留，不静默丢弃编辑。
- 首次空设备下载；已经连接的设备丢失源文件时产生待核对冲突，不自动清空云端。
- 字段白名单、设备配置分离、附件内容排除；四份小院存储的下载检查点、失败后恢复与新编辑保护。
- 未认证、错误 owner、失效 Auth 会话、越权 scope、未配对及已撤销设备拒绝访问；自我撤销不继续读取已失去权限的列表。
- 同源不同 ID 的明确处理：保留云端条目、把当前本机笔记留在恢复记录；普通移除仍保留来源抑制，旧身份不能自动复活删除。
- 原来的 30 天期限、永久删除、学习时间线到期，以及同步缓存中的过期内容最小化；下载事务载荷变化时使用新检查点身份。
- Codex / Claude Code 缺失安装、未登录、探测失败与未验证模型访问；选中上下文预览不执行命令、不读取任意文件、不自动立项。
- 跨设备共享项目身份与各自目录/原生会话的分离；项目删除保留外部工具、原始文件、代码及 GitHub 仓库。
- 本机 Git、远程跟踪引用与明确查询的 GitHub API 来源和时间，浅历史及分页提示；查看不偷偷 fetch。

视觉审阅已清除草稿丢失与计数歧义两项问题，保留已有像素花园体系。普通扩展未修改 DESIGN.md 或其 sidecar；其中旧导航名称、较早的主题说明和按钮样例存在既有文档偏差，未将本次实现作为设计系统更新。

## 实际限制

本地 PostgreSQL 测试不是托管 Supabase 的完整验收。创建资源后仍需关闭注册、配置唯一 owner 和设备、检查 Data API 暴露范围及安全建议，再以合成账户进行联网授权/撤销验证。首次真实迁移需要重新核对当前 Windows 与云端的最新预览。

附件字节同步、跨 ID 自动笔记合并、本机备份自动清理、原生对话跨设备恢复及模型调用验证尚未实现。Windows 和 macOS 的实机跨设备同步仍待云端部署后验证。操作与恢复步骤见 [私人云端同步](private-cloud-sync.md)。
