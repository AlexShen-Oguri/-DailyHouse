# 项目续航入口与学习进度小卡：首版方案

**状态：方案说明，尚未实现，等待你选择。** 本文不代表这两个功能已经接入，也不会触发项目操作、创建待办或改写学习计划。

两项功能都复用已有本机文件：项目续航帮助找回项目的下一步，学习小卡帮助从现有计划里挑出今天愿意推进的事。可以只选其中一项，也可以两项都不加。

## 1. 项目续航入口

### 打开后会看到什么

你固定少量项目目录，例如 Glass Notes 或 Ponytail。每个项目占一张小卡，展示项目名称、当前阶段、当前任务、任务状态、下一步，以及状态记录的更新时间。卡片下方提供 `CURRENT-STATE.json`、`HANDOFF.md`、`README.md` 的打开入口，并分别标出文件修改时间。

有结构化状态的项目显示具体字段；只有 README 的项目仍可作为文档入口，但显示“尚无结构化状态”，不计算完成率、不根据文件多少或提交次数推测进度。

### 数据从哪里来

首版支持已经核验过的 JSON 结构。项目目录下的 `planning/CURRENT-STATE.json` 或 `CURRENT-STATE.json` 是优先来源；若同时存在多个候选文件，绑定时由你明确选定一个，后续始终显示该来源。

| 卡片内容 | 首选字段或文件 | 处理方式 |
| --- | --- | --- |
| 项目名称 | 你设置的显示名称 | 可以用简短别名，不需要在卡片上展示完整目录。 |
| 当前阶段 | `product.phase` | 原样显示；兼容明确使用顶层 `phase` 的文件。两处值不同则提示冲突。 |
| 当前任务 | `task.title` | 缺少字段时显示“未提供当前任务”。 |
| 任务状态 | `task.status` | 与项目整体状态分开；不把 `product.status` 当成任务状态。 |
| 下一步 | `task.nextAction` | 仅作为来源记录展示，点击后才能加入待办。 |
| 状态记录更新时间 | `updatedAt` | 有效时间才显示为“状态更新于”；不会用文件修改时间冒充。 |
| 文件修改时间 | 文件系统 `mtime` | 单独显示“文件修改于”，便于发现文档与状态记录可能不同步。 |
| 交接与说明 | `docs/HANDOFF.md` / `HANDOFF.md`、`README.md` | 只提供已存在文件的打开入口；不从正文自动归纳项目进度。 |

若其他项目采用顶层 `status`、`nextAction`，只有在对应 `task` 字段缺失时才兼容读取，并清楚显示实际来源字段。字段类型异常时显示“字段无法读取”，保留查看原文入口。

### 你如何使用

1. 添加项目，选择固定目录和显示名称；确认卡片使用哪个状态文件。
2. 打开工作台时查看卡片；点击“刷新”重新读取文件。
3. 点击文档入口，在工作台中只读查看已绑定目录内的文档。文档中的代码块只是内容，不会被当成命令执行。
4. 需要推进时，点击“将下一步加入待办”。先看到待办标题和来源，可缩短或改写标题，确认后加入现有的手动待办。

首版不启动开发服务器、不执行构建或 Git 命令，不自动改项目文件，也不自动续接任何历史对话。项目的状态文件继续由原有工作流程维护。

## 2. 学习进度小卡

### 打开后会看到什么

一张小卡显示当前阶段、来源记录更新时间，以及**最多 3 个明确提出且尚未完成的事项**。每项旁边都有“查看出处”和“加入待办”。卡片不把整份长期路线图铺成任务清单，也不生成进度百分比。

“计划建议”和“已明确的待办”有不同标记。默认显示明确待办；建议收在可展开区域，只有你选择并确认后才成为工作台待办。

### 只读取第 14 节的动态状态

现有 Development Plan 的第 1–13 节是长期方向、路线与使用规则，第 14 节才是持续更新的学习记录。首版只从第 14 节提取动态内容，不能因为路线图写着“第 2 周”就自动宣布已经进入第 2 周。

| 卡片内容 | 第 14 节中的来源 | 处理方式 |
| --- | --- | --- |
| 当前阶段 | “当前状态”下的“当前阶段” | 保留原文表达，不根据当前日期推算周次。 |
| 来源记录更新时间 | “最近一次访谈”等明确记录的时间文字 | 原样保留记录语义；另外展示文件修改时间。没有明确记录时间时显示“记录时间未提供”。 |
| 明确待办 | 明确标为用户提出、尚未完成的事项，以及有明确确认依据的状态条目 | 最多显示 3 项，沿用来源顺序；其余通过“查看原计划”访问。 |
| 建议 | “建议下一步”“建议节奏”、明确注明属于计划建议的任务区 | 独立标记为建议，不直接进入待办候选。 |
| 已完成记录 | 明确确认完成的文字或具有明确含义的完成标记 | 不再作为待办候选。生成了材料、提供了链接，不能等同于已经学习或阅读。 |
| 来源位置 | 第 14 节中的小节、条目及原文片段 | 支持回到出处核对；路径只保存在本机设置。 |

解析以约定标题和明确状态为边界，不让模型自行猜测完成情况。长段落无法可靠拆分、事项究竟是建议还是承诺不清楚时，显示“需要确认”，让你查看原文，而不是自动造出任务。

### 你如何使用

1. 选择已有 Development Plan 文件；预览并确认识别到了第 14 节。
2. 查看当前阶段与最多 3 个明确待办；需要更多信息时打开原计划。
3. 选择一项，确认标题后加入现有手动待办。计划中的建议也可由你明确选中后加入。
4. 在工作台勾选完成，只改变这条本机待办。源计划保持原样，并可显示“工作台已完成，原计划尚未同步”。需要更新源计划时，由你沿用原来的编辑或访谈流程处理。

## 3. 重复、过期与来源冲突

| 情况 | 首版表现 |
| --- | --- |
| 未绑定目录或学习文件 | 显示“选择来源”，不使用演示进度。 |
| 项目没有状态 JSON | 仍可打开 README / HANDOFF；阶段、任务与下一步显示未提供。 |
| 学习文件没有第 14 节 | 显示“未找到动态学习记录”，不把第 1–13 节当作当前进度。 |
| 文件移走、权限不足、JSON 损坏或格式变化 | 明确显示读取失败，提供重新选择来源或查看文件；不把上次成功读取的内容伪装成最新状态。 |
| 来源超过 7 天未更新 | 提示“超过 7 天未更新”并显示具体日期。这是首版拟定的提醒阈值，不代表项目停滞或学习落后。 |
| 缺少状态更新时间，只有文件 `mtime` | 只显示“文件修改于”；不据此判断实际进度是否更新。 |
| 状态 JSON 与交接文档时间不同 | 标出各自时间，提醒核对。结构化字段用于卡片展示，HANDOFF 保留原文入口，不静默合并矛盾结论。 |
| 同一学习事项既出现“完成”又出现“未完成” | 标记“来源状态冲突”，不自动选择其中一个；核对后再加入待办。 |
| 同一下一步已加入待办 | 显示“已加入”并跳转原待办，不重复创建。 |
| 对应待办已完成，但源文件仍未更新 | 保留工作台完成状态，提示来源尚未同步；不自动重新创建或重新打开待办。 |
| 来源内容后来改变 | 已加入的待办标题不会被静默改写；展示来源有变化，供你决定是否调整。 |

去重以本机来源标识为主：绑定的项目或学习文件、条目位置或任务 ID、规范化后的事项文字。确认添加时，再检查现有同名未完成待办，避免与手动创建的事项重复。仅仅调整空格或重新刷新不产生新任务。

## 4. 本地实现范围与选择

首版可以直接复用现有本地后端、设置和手动待办。新增的只是来源绑定、受限文件读取、字段映射，以及“来源条目 ↔ 已加入待办”的本机记录。只读取你绑定的目录和文件；不全盘扫描，不跟随符号链接越界，不读取无关文件，也不需要外部连接器或额外定时任务。

显示名称、来源路径和去重记录保存在被 Git 忽略的个人数据中。项目仓库只保存通用解析规则、界面和测试夹具；不提交个人绝对路径、实际任务内容或学习状态。此方案文档也只描述文件结构与行为。

如果选择实施，建议放在“我的小院”的两个小区域，通过现有待办页继续处理任务，无需为了它们增加两套独立任务系统。最终可以选择“只做项目续航”“只做学习小卡”“两项都做”或“暂不添加”。在你选择前，这两项保持为方案。
