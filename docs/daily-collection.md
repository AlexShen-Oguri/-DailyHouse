# 每日小院采集

每天纽约时间09:45由专用「小院日常采集」对话执行，不再占用网站开发对话。使用与书架按钮相同的已实现流程；每次内容判断由当前项目中的独立 Codex「书架收集」对话完成。

## 执行顺序

1. 检查 `http://127.0.0.1:3456/api/health`。服务未运行时用 `scripts/Start.ps1 -NoBrowser` 启动；正常服务不重启，不修改源码，不提交Git。
2. `GET /api/personal/reading` 发现已生成的正式科技、设计 PDF；`POST /api/personal/calendar/refresh {}` 读取已经配置的日历。来源不改、报告不重新生成；尚未完成的报告跳过，其他流程继续。
3. `node scripts/reading-import.mjs status` 检查现有读取；有运行中的任务则等待，否则 `node scripts/reading-import.mjs read` 启动。浏览器扩展读取登录的B站页面，不使用cookie、密码或私人历史接口。
4. 间隔15–30秒读取status，直到completed/partial/needs_login/failed/cancelled。超过10分钟仍未完成则准确报告当前状态，不重复开启、不伪造完成。
5. 服务端固定验证7×24小时、已知进度低于25%、最新记录、重复和移除抑制，再由独立Codex对话直接选择实用内容并归入现有分类。无待确认、acceptedUrls或批次审阅。读取摘要只保留最近五次。

## 日报自动出现

每天09:00的科技早报与设计图鉴制作独立运行。正式PDF一旦写到已配置目录，书架打开或自动刷新即可显示，即使09:45时尚未完成也不会漏掉稍后到达的文件。网页可见时每60秒刷新，重新打开时补上关闭期间的日报。已移除和已完成状态不重置。

## 运行条件与结果

电脑、Codex、本机服务和登录B站的浏览器需可用。采集时浏览器窗口会被带到前台一次，应保持历史页可见；后台加载中断会标为部分读取。模型不可用时明确失败，可在书架重试，不降低规则、不新增审阅队列、不改个人JSON或回滚数据。

无新增、无新的可处理问题时保持安静。新增内容时简要告知数量与书架入口；需要恢复登录或持续失败时说明操作，不重复通知未变化的问题。最多保存最近五次本机执行摘要，不保留详细观看清单。不得读取银行账户、触发灵感草稿、生成报告或开发新功能。
