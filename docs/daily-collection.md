# 每日小院采集

已启用 Codex 当前任务的「每日小院采集」，每天纽约时间 **09:45** 运行，接在现有 09:00 科技早报、审美图鉴之后。它不重新生成日报。调度随纽约夏令时变化；电脑须开机、Codex 须运行，B站需保持登录。网页单独打开不等于调度器在运行。

## 一次采集的流程

1. 检查本机工作台健康状态；必要时通过已有 Start.ps1 启动。正常运行时不重启、不改代码、不提交 Git。
2. 请求书架，发现已配置日报目录里的正式 PDF；请求日历刷新，读取当前配置的在线订阅或本地 ICS。来源未配置时跳过，不修改设置。本地 ICS 是快照，不会自行更新。
3. 通过已授权的浏览器页面读取最近 **7 × 24 小时** B站历史：标题、BV 链接、观看时间、已知播放比例、可见封面。实际读到哪一段就记录哪一段，登录失败或页面没读完不能记为完整覆盖。不读取浏览器凭证、私有接口，不绕过验证。
4. 同一 BV 使用最近一次观看证据；进度未知不能当成零。保存被 Git 忽略的 `.runtime/*.local.json`，用 `node scripts/reading-import.mjs preview <文件>` 预览，再 `apply` 提交。服务端重新校验最近一周、低于 25%、分类、重复与移除抑制。
5. 明显娱乐排除，不明确的留在批次待确认，不替用户确认。新增条目保存后，由服务端排队请求本机 Qwen 进行主题分类；低置信提示确认，失败保留条目并可重试，不重复导入同一批以重试分类。已记录的相同待确认候选不每天新增空批次。手动改过的分类、已完成和已移除内容不会被自动覆盖或重新加入。
6. 每次在 `.runtime` 留本机日志：时间、来源、实际覆盖、新增与待确认数量、错误及重试建议。有有意义的新增、失败或需要登录时通知；无变化和相同未解决问题保持安静。

这是一条带浏览器步骤的条件式自动采集流程。登录过期、平台页面变化、机器休眠或报告尚未生成都可能使当日结果不完整；恢复后下一次仍重读最近一周，依靠来源身份去重。当前不承诺平台提供稳定的历史 CLI，也不宣称已经执行过未来的一次定时运行。

## 导入之后

- 新内容进入「未完成」，支持编辑分类、笔记、单项/批量/全部移除。
- 完成后打勾淡出，保存在「已完成」，可重新开始。
- 移除进入 30 天回收站，可恢复；来源抑制防止次日重新导入。
- 批次可查看覆盖、分类理由和异常，可撤销其新增且尚未被手动修改的记录。
- 自动 Qwen 分类不妨碍批次撤销；手动修改仍受保护。分类暂时失败不阻断日历或日报采集。
- 日报和视频只保存本地入口，不删除源文件或平台内容。

详细输入和撤销规则见 [书架导入说明](reading-import.md)。当前采集不包括银行自动登录、Obsidian 写入、Git 项目状态采集或自动生成灵感。暂停/改时间应修改已有「每日小院采集」，不要重复创建任务。
