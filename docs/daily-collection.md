# 每日小院采集

每天纽约时间（`America/New_York`）10:00由已配置的「每天10点 B站书架采集」任务在用户确认的采集对话中执行，使用本机已登录 B站的 Chrome。使用与书架按钮相同的已实现流程；每次内容判断由当前项目中的独立 Codex「书架收集」对话完成。

## 执行顺序

1. 检查 `http://127.0.0.1:3456/api/health`。Mac 服务未运行时用 `./Start.command --no-browser` 启动，Windows 使用 `scripts/Start.ps1 -NoBrowser`；正常服务不重启，不停止无关进程，不修改源码，不提交Git。
2. 确认 Chrome 已登录 B站，项目采集扩展与本机服务已连接。第一次使用需在 `chrome://extensions` 加载项目的 `extensions/bilibili-reading` 文件夹。未连接时报告真实原因，不伪造连接或历史。
3. Mac 使用已验证的项目本地 Node.js 24 执行 `.runtime/node/bin/node scripts/reading-import.mjs status`，Windows 使用 `node scripts/reading-import.mjs status`；有运行中的任务则等待，否则使用相同运行时执行 `scripts/reading-import.mjs read` 启动。浏览器扩展读取登录的B站页面，不使用cookie、密码或私人历史接口。
4. 间隔15–30秒读取status，直到completed/partial/needs_login/failed/cancelled。超过10分钟仍未完成则准确报告当前状态，不重复开启、不伪造完成。
5. 服务端固定验证7×24小时、已知进度低于25%、最新记录、重复和移除抑制，再由独立Codex对话直接选择实用内容并归入现有分类。无待确认、acceptedUrls或批次审阅。读取摘要只保留最近五次。

本任务只采集 B站，不触发日历刷新、报告制作或其他来源采集。任务启用不代表某一次读取已成功，结果以实际状态为准。

## 日报自动出现

每天09:00的科技早报与设计图鉴制作独立运行。正式PDF一旦写到已配置目录，书架打开或自动刷新即可显示，即使10:00时尚未完成也不会漏掉稍后到达的文件。网页可见时每60秒刷新，重新打开时补上关闭期间的日报。已移除和已完成状态不重置。

## 运行条件与结果

电脑、Codex、本机服务和登录B站的浏览器需可用。采集时浏览器窗口会被带到前台一次，应保持历史页可见；后台加载中断会标为部分读取。模型不可用时明确失败，可在书架重试，不降低规则、不新增审阅队列、不改个人JSON或回滚数据。

可在 Codex 的任务卡中停用或删除定时任务；在 Chrome 扩展管理页禁用或移除采集扩展会断开采集连接。这些操作不删除书架内容。

无新增、无新的可处理问题时保持安静。新增内容时简要告知数量与书架入口；需要恢复登录或持续失败时说明操作，不重复通知未变化的问题。最多保存最近五次本机执行摘要，不保留详细观看清单。不得读取银行账户、触发灵感草稿、生成报告或开发新功能。
